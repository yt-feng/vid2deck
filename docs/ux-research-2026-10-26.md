# Vid2PPT 新用户引导与渐进交互研究

调研日期：2026-10-26。当前产品诊断基于生产对应提交 `2340c0a` 的代码与页面结构；下列外部案例通过 GitHub 源码、项目 README 和官方文档核验。案例证明交互方式存在，不代表已经证明其能提高 Vid2PPT 转化率。本文是设计依据，实际落地及验收以本轮实现记录为准。

## 核心判断

Vid2PPT 已有示例、来源标签、步骤条和草稿恢复，但新用户仍需自己推断“此刻该做什么”。优先缩短到第一份可用笔记的路径，让每个阶段提供一个明确的下一步，并在完成之后再展开编辑、AI 要点与其他格式。

当前主要阻力：

1. `public/global-home.js` 会把普通首页访问转向 `/welcome/`；欢迎页“开始”又跳回 `/#start`，再次出现完整产品介绍和导入卡。用户已决定开始，却又进入第二个介绍页面。
2. 同一行为有“立即生成”“获取并开始生成”“开始当前任务”“开始整理笔记”等表述；“仅导入”和主操作同时出现，让新用户先理解内部队列概念。
3. 工作台在没有素材时就出现格式导出、编辑、全选和大量失效按钮。步骤条说明阶段，却没有把当前阶段转成一个可执行的小目标。
4. 默认阅读结果已经合理，但“原画面笔记”“图文笔记”“AI 要点”“逐字稿”“页面编辑”的入口互相竞争。没有文字时，阅读区说明首先引导复杂的语音模型/登录流程，会削弱已有画面成果。
5. 示例直接打开完整工作台。用户能浏览，却缺少“读一页 → 调整选页 → 带走 → 用自己的视频”的明确递进；示例中的作者文字也应持续标明来源。

## 四个参考产品与可迁移方式

| 产品与已核验证据 | 可迁移到 Vid2PPT 的方式 |
| --- | --- |
| **Excalidraw**：`WelcomeScreen.Center` 把加载文件、帮助放进真正的编辑画布；`WelcomeScreen.Hints` 的提示贴近菜单、工具栏和帮助入口。不是先看独立教程再进入另一套界面。[中心组件](https://github.com/excalidraw/excalidraw/blob/master/packages/excalidraw/components/welcome-screen/WelcomeScreen.Center.tsx)、[就地提示源码](https://github.com/excalidraw/excalidraw/blob/master/packages/excalidraw/components/welcome-screen/WelcomeScreen.Hints.tsx)。 | 欢迎页的“开始”直接进入导入状态；新手帮助放在真实来源控件、页面选择、导出按钮附近。避免新增必须点完的浮层教程。 |
| **Cal.com**：官方创建流程先填写基本信息，再按类型显示参与人配置，之后调整可用时间；高级设置分在后续标签中。GitHub 的 `calcom/cal.com` 当前重定向到 `calcom/cal.diy`，本次没有把两者线上版本视为完全相同。[官方创建流程](https://cal.com/blog/event-types-guide-calcom)、[当前公开仓库](https://github.com/calcom/cal.diy)。 | 先决定来源，推荐设置即可开始；提取参数、OCR、逐字稿等放在需要时再展开。可选能力不能变成第一份笔记的必经步骤。 |
| **Typebot**：编辑和发布状态明确分开；修改不会自动覆盖发布版，用户能恢复已发布版本。官方 Graph 文档也明确指出未连接下一步会使流程停止，说明仅呈现功能节点不等于顺畅的任务流。[发布状态](https://docs.typebot.com/editor/publish)、[流程连接说明](https://docs.typebot.com/editor/graph)、[公开仓库](https://github.com/baptisteArno/typebot.io)。 | 区分“素材已导入”“笔记可阅读”“已发起导出”，每个状态有相应下一步。重新提取不丢已编辑结果；失败保留可用成果。将完成态与后续增强分开。 |
| **tldraw**：官方持久化文档区分文档数据和用户会话状态，支持 IndexedDB 自动保存与快照恢复。[持久化说明](https://tldraw.dev/docs/persistence)、[公开仓库](https://github.com/tldraw/tldraw)。 | 返回用户直接看到“继续上次任务”，恢复原文件、勾选和当前阅读位置；示例保持独立，退出后恢复真实任务。保存反馈不要求用户理解数据库实现。 |

许可说明：上述是公开 GitHub 产品的交互研究；Typebot 自称 Fair Source，tldraw 的 SDK 有自身许可。这里提炼交互原则，不复制其实现代码。

## 本轮优先做的五个模式

| 优先级 | 模式 | 用户可见行为 | 验收条件 |
| --- | --- | --- | --- |
| P0 | 一次开始就进入任务 | 欢迎页开始按钮直达聚焦导入视图；保留返回产品介绍的入口 | 开始后不用再次阅读整屏营销内容；直接使用文件/链接/录屏；深链接仍有效 |
| P0 | 每个阶段只有一个推荐下一步 | 未选素材→选择视频；素材就绪→开始整理；处理完成→阅读笔记；阅读后→保存；错误→当前来源的重试或替代输入 | 状态、按钮文案和实际动作一致；不能把阶段名称当作按钮；无素材时不堆禁用导出按钮 |
| P0 | 示例通过真实小动作教会用户 | 示例打开即可读，提示检查画面，再选页/导出；完成后“换成我的视频” | 不占额度；可跳过引导；真实操作推进状态；示例与真实草稿隔离 |
| P1 | 先完成成果，再按需加深 | 默认先阅读已有原画面笔记；编辑和 AI 要点为可选分支；导出给出格式用途 | 无需注册和转写就能完成原画面导出；原画面已可用时不以 AI 未完成阻塞；用户知道 PDF/PPTX/完整笔记各带走什么 |
| P1 | 完成和回访有连续性 | 发起保存后说明已生成的格式与下一步；返回时优先继续真实任务；可再次下载 | 点击导出成功后才更新完成态；失败不更新；不宣称浏览器已实际写入用户磁盘；刷新和切换示例不丢选择 |

## 建议任务路径

新用户：**看懂结果 → 直接选择来源 → 默认设置开始 → 看见处理反馈 → 阅读结果 → 按需要调整 → 保存第一份笔记**。

没有素材的用户：**打开示例 → 阅读一页 → 体验选页 → 保存示例 → 换成自己的视频**。

回访用户：**继续上次任务 → 保留上次选择 → 直接阅读/编辑/再次导出**。

AI 要点是完成第一份原画面笔记后的增强分支，登录发生在用户明确选择该能力时；提取参数属于高级调整，首次使用推荐默认值。新手引导应可跳过、可重开，并尊重减少动态效果的系统偏好。

## 衡量方式

首要观察真实素材任务的首次成功导出生成率，以及“进入导入 → 有效素材就绪 → 第一个可读页面 → 导出生成”的耗时与流失。示例单独看打开、真实交互、导出及切换自己素材的比例。不要把打开工作台、点击下载按钮或查看套餐当成用户已完成任务。先建立前后可比的来源、设备、素材长度分组基线，再判断改版效果。
