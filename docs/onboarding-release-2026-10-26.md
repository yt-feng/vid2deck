## 产品判断与改动

新用户需要先完成一次「导入 → 自动提取 → 检查 → 导出」，每个阶段有明确的下一步。研究来源、证据与设计取舍见 [公开产品交互调研](ux-research-2026-10-26.md)。

| 原来的断点 | 本轮实现 |
| --- | --- |
| 欢迎页开始后再次看到产品介绍，示例入口不显眼 | 欢迎页并列提供自己的视频和免费示例；主操作进入专注导入；预览图成为真正可点击和键盘访问的示例入口 |
| 一进入结果就看到多种导出和 AI 操作 | 状态驱动的下一步引导，先检查页面；熟练用户可以直接导出；AI 内容位于原画面之后，笔记附加操作收进菜单 |
| 示例打开后没有完成目标 | 3 页示例支持检查、排除页面、真正生成文件，然后转到自己的视频；不消耗转换次数 |
| 用户需先理解多种文件格式 | 单一导出窗口按用途解释：PDF 复习打印、PPTX 演示分享、HTML 完整笔记；Markdown 和图片 ZIP 放在其他格式 |
| 导出之后不知是否完成或下一步做什么 | 文件生成成功后显示下载列表提示；可继续其他格式或下一段视频；修改选页、顺序或文字后不沿用旧完成状态 |
| 小屏导航拥挤、较矮屏幕看不到下载按钮 | 手机辅助导航进入可关闭菜单；导出窗口主体独立滚动，下载按钮常驻 |
| 再次选择视频仍留在旧任务 | 默认切到新选视频，旧任务及编辑保留；普通文件导入在下载期间仍被互斥保护 |
| 语言切换丢失示例或帮助位置 | 中英文共用完整交互，新增提示单独校正文案，语言切换保留任务和帮助深链接 |

中文和英文工作台共用 DOM、状态推导与处理函数；英文动态文件名、用户内容和识别内容不参与翻译替换。欢迎页新入口同时补齐现有 33 个营销语言字典。

- 新增测试覆盖阶段推导、空选页、处理中保留旧结果、异步导出快照、内容变化后完成状态失效、失败重试、示例直接导出、新视频切换、忙碌互斥、空工作台入口、中英文路由及工作台返回帮助内容的可见性。

- Chrome 英文示例：直接导出 PDF，实际下载文件 **3 页**。

- 真实提取结果生成 HTML 笔记，实际文件含 **3 张内嵌原画面**。
- 页面重新打开后，中文入口恢复同一测试任务的 **3 页**结果；示例退出回到自己的视频入口。
- 390×844 手机尺寸检查中文欢迎页、中文恢复任务、英文导入和英文提取结果；中文手机菜单展开和 Escape 关闭正常；导出选择和完整笔记生成正常。
- 本地预览的 API 登录、支付和联网 AI 服务未作为本轮成功结论；本轮没有执行真实支付或登录提交。

上述文件生成检查不等同于由 PowerPoint 人工打开文件，也不代表一般视频的提取准确率。合成视频用于验证导入、去重、状态推进及交付连续性。
