日期：2026-09-08  
范围：当前工作区的首页、工作台、账号入口、定价、赞助、隐私、条款及退款说明。  
环境：已完成本地验证，并于 2026-09-08 发布到现有 Vercel 生产项目；正式域名 https://vid2ppt.com/。

## 1. 本次优化解决什么问题

产品主任务是「导入视频 → 提取页面 → 检查修正 → 导出资料」。本次围绕这条旅程调整信息顺序、交互反馈与失败恢复，保留已有原画面提取、OCR、转写、笔记和辅助工具。

验收区分四种证据：**浏览器实测**、**自动化测试**、**代码检查**、**尚未验证**。内置示例用于验证工作台操作，不代表某段真实视频的识别效果；生成导出文件、触发下载、文件实际可打开是不同的验收步骤。

| 用户遇到的问题 | 本次实际改动 | 用户得到的结果 |
| --- | --- | --- |
| 首屏同时出现链接、上传、录屏、批量、逐字稿等信息，难以判断从哪一步开始 | 来源改为本地文件、视频链接、录屏三个标签；本地导入默认展示；主文案收敛到页面提取和导出 | 第一次只需决定视频来源；后续能力在需要时再出现 |
| 首页重复介绍格式、功能与竞品差异，滚动较长，却未充分解释实际输出 | 合并流程示意与三步说明；精简功能卡；增加视频适用条件；明确 PPTX 默认保留原画面、OCR 另行识别文字 | 用户能先判断素材是否适合，以及导出后哪些部分可编辑 |
| 手机导航隐藏了部分入口，页内链接在工作台打开时可能无法定位首页 | 增加可展开菜单、常驻免费开始、跳过导航；支持 Escape、焦点恢复及首页/工作台 hash 路由 | 手机可访问完整导航；返回指南、工具、账号或导入区时有明确落点 |
| 已有图片/PDF 工具和页面主线连接较弱 | 保留全部辅助工具，将其放在 FAQ 前并提供导航入口 | 已有素材用户无需进入视频流程，也能找到对应工具 |
| 提取过程中只看到忙碌状态，不清楚进度、能否停止以及结果在哪里 | 工作台增加步骤提示、扫描进度、实时页面、停止提取；统一结果导出入口 | 用户知道当前阶段，能检查逐步出现的页面，按需停止 |
| 已处理任务可能被重复提取、失败或误操作覆盖 | 有结果时优先继续检查；重新提取增加明确选择；失败恢复已有结果；支持撤销上次页面操作 | 可以继续已有任务，减少重新整理 |
| 返回首页、查看示例、刷新后继续工作的体验不连贯 | 页面状态保存；示例退出恢复原任务；加入本机草稿保存与恢复入口、保存失败反馈 | 用户可回到原有编辑状态；本机保存不可用时能及时知道 |
| OCR、转写等异步操作可能在额度检查期间重复启动，失败后丢失旧内容 | 在异步检查前锁定任务；拒绝后解锁；失败保留旧稿、文字框或图片底图 | 重复点击不会同时启动多个同类任务；失败后仍有可用结果 |
| 批量任务遇到一个坏视频后，其他正常文件难以继续交付 | 按文件记录失败并继续处理；成功文件单独打包；用量按成功转换记账 | 能先交付成功结果，再针对失败文件重试 |
| 付费入口直接跳向支付，套餐、邮箱和当前账号关系不够清楚 | 改为选择套餐→核对权益与购买邮箱→继续支付；加入完整套餐表、FAQ、邮箱匹配说明 | 用户在发起支付前能检查自己买什么、绑定到哪个账号 |
| 支持页面导航和问题解决入口不统一 | 统一定价、赞助、条款、隐私与退款导航；退款页增加取消订阅/未开通入口；赞助页增加订单找回与复制回退；隐私说明补充最近一次本机草稿的保存、恢复、替换与删除方式 | 能从具体问题找到对应说明或支持入口 |

## 2. 关键产品规则

- 免费版支持每段不超过 10 分钟的视频、每月 3 次转换；首页来源区域展示当前套餐与剩余额度。
- 默认导出原始页面画面。可编辑文字来自 OCR 文本框，复杂图表不自动还原为原始图形对象。
- 本地视频与录屏在设备上抽帧和去重；链接导入、摘要等联网能力单独说明处理方式。
- 内置交互示例不占转换额度，也不作为真实视频的识别准确度证明。
- 逐字稿、摘要和图文笔记属于按需能力，用户无需等待它们完成才导出页面。
- 本轮保留已有价格和商业条件；隐私说明按新增本机草稿行为补充。选择套餐、创建订单、付款完成、账号权益生效分别处理。

## 5. 下一步如何衡量体验是否改善

建议先在自有系统中定义事件和聚合口径，再决定采集实现。本文不默认接入第三方统计，也不把按钮点击等同于任务完成。

| 指标 | 建议口径 | 用来回答的问题 |
| --- | --- | --- |
| 首次开始率 | 首次成功读取有效素材的会话数 / 首次访问首页的会话数；排除示例 | 首屏是否让新用户知道如何开始 |
| 来源导入成功率 | 成功得到可解码素材的任务数 / 按来源提交的任务数 | 本地、链接和录屏各自哪里最容易中断 |
| 首次出页时间 | 素材通过校验到首个可检查页面出现的耗时；按素材长度、来源分组看中位数与 P90 | 等待反馈是否足够快 |
| 提取完成率 | 提取完成任务数 / 通过素材校验并开始提取的任务数 | 用户是否能够走到结果页 |
| 停止与失败原因分布 | 分别记录主动停止、额度限制、解码失败、下载失败、服务失败等类别 | 应优先改进哪一段流程 |
| 结果修正率 | 有删除、补抓、裁剪或排序行为的任务数 / 有页面结果的任务数 | 默认提取结果是否需要大量整理 |
| 首次导出生成率 | 第一次会话内成功生成非空导出文件的任务数 / 有可检查结果的任务数 | 工作台是否帮助用户走到交付 |
| 导出质量抽检 | 对抽样产物检查可打开、页数、顺序、中文及文本层；另记用户确认 | 生成的文件是否真正可用 |
| 继续任务成功率 | 从恢复入口打开且结果与保存状态一致的任务数 / 恢复尝试数 | 本机保存是否减少重新开始 |
| 免费试用后的升级意向 | 先完成一次真实导出后再选择付费套餐的会话数 / 完成真实导出的免费会话数 | 付费意向是否建立在体验价值之后 |
| 付费兑现率 | 付款确认且账号权益正确生效的订单数 / 付款确认订单数 | 支付完成后是否实际获得所购能力 |
| 支持问题分布 | 按导入、识别、导出、账号、付款、权益分类记录支持请求 | 哪类问题仍使用户离开主流程 |

建议的最小事件序列为 `source_selected`、`source_validated`、`extraction_started`、`first_page_ready`、`extraction_finished`、`extraction_stopped`、`task_failed`、`review_action`、`export_generated`、`draft_restored`、`plan_selected`。支付确认与权益生效应来自相应服务记录。

事件只需要临时任务标识、来源类别、耗时、素材长度区间、页数、导出格式、错误类别和当前套餐类别。无需收集视频内容、逐字稿、文件名、完整来源链接或邮箱。浏览器触发下载只能说明下载动作已发起；「已保存到用户设备」需要额外的可验证依据。

先采集一个稳定基线，再按设备与来源比较改版后的变化。上线前不预设虚假的提升百分比；优先看真实任务完成和产物质量，再看转化速度与付费意向。
